FIT 文件生成器完整操作说明

适用版本：v2.3.0 · Windows 64 位与 Android 8.0 及以上版本

本应用根据你设置的运动参数和路线，在本机生成 .fit 文件。路线可以来自标准体育场跑道，也可以来自自己的 GPX 轨迹。生成文件不需要登录账号。

1. 下载、安装与打开说明

从本项目的 GitHub Releases 下载文件。文件名里的版本号应与本说明一致。

Windows

  1. 下载 fit-file-generator-v2.3.0-windows-x64.exe，放到一个方便找到的文件夹。
  2. 双击 EXE 即可运行，无需安装 Python，也无需安装器。
  3. 主界面右上角的“操作说明”会在默认浏览器中打开内置说明，离线也能阅读。
  4. 如果 Windows 提示发布者未知，先确认下载来自上述项目发布页，并用发布附件 SHA256SUMS.txt 核对文件。本版本 EXE 未做代码签名。

校验示例：在 EXE 所在文件夹打开 PowerShell，运行 Get-FileHash .\fit-file-generator-v2.3.0-windows-x64.exe -Algorithm SHA256，将输出与校验文件中的同名记录比较。

Android

  1. 下载 fit-file-generator-v2.3.0-android.apk，点击文件，按手机提示允许该下载来源安装应用。
  2. 安装后打开“FIT 文件生成器”。生成文件和导入 GPX 使用系统文件选择器，无需授予存储权限。
  3. 主界面标题区的“操作说明”可打开内置说明；左上方“返回”按钮回到应用。
  4. 只有点击“使用当前位置”时才需要定位权限；也可以直接通过地图或手动坐标设置跑道。
  5. 正式发布 APK 沿用本项目原有签名，可以覆盖升级原正式版。若手机装的是另一种签名的调试版，可能无法直接覆盖；先保留已导出的 FIT 文件，再处理旧版本安装。

发布页同时提供独立 HTML 和 Markdown 说明。HTML 文件可在手机或电脑的浏览器中离线打开。

3. 第一次生成：标准跑道示例

以下以“5 公里、30 分钟、170 步/分钟”为例。跑道中心请选你自己的实际位置，不要套用示例中的其他人的坐标。

Windows 操作顺序

  1. 在“运动数据”填写距离 5、时长 30、平均步频 170；步幅先留空。
  2. 点击“打开地图 · 选点 / 查看路线 ↗”。在地图页输入学校、体育场或城市名称，点击“查找”。
  3. 选择匹配的结果，放大到跑道位置，点击实际跑道中心；拖动蓝色中心点可以微调。
  4. 调整跑道方向、直道长度和半圆弯道半径，让轮廓与实际跑道尽量吻合。
  5. 点击“应用到 .fit 文件生成器”，回到桌面程序，检查回填的坐标和尺寸。
  6. 设置“开始日期”和“开始时间”。生成份数设为 1，点击“选择保存文件夹…”选择输出位置。
  7. 查看右侧指标：配速应约为 6′00″ /km，自动步幅约为 0.9804 米/步。默认尺寸约为 400 米一圈，对应约 12.5 圈。
  8. 点击“生成 .fit 文件”，等待“已生成 1 份 FIT 文件”提示。
  9. 点击“打开输出文件夹”，找到 run_...fit 文件。

Android 操作顺序

  1. 在“运动数据”填写距离 5、时长 30、平均步频 170；步幅先留空。
  2. 下滑到“跑道与坐标”，点击“地图校准 / 查看”。
  3. 搜索学校或体育场，点选实际跑道中心，调整方向、直道长度和半径。
  4. 点击地图中的“应用校准”，回到主界面，检查预览和指标。
  5. 在“开始时间”选择日期和时间。
  6. 点击底部“保存 FIT 文件”。在系统文件选择器里选择下载目录或其他位置，并确认保存。
  7. 等待“已保存到手机”提示；随后在文件管理器中到刚才选择的位置查找文件。

如果不使用在线地图，可以手动填写已知的准确坐标与跑道尺寸，再直接生成。

4. 地图校准与坐标来源

中心、方向和尺寸怎么选

  • 中心是整个跑道几何形状的中心，不是校门、操场入口或跑道边缘。
  • 方向是跑道长轴从正北顺时针旋转的角度：0° 表示南北方向，90° 表示东西方向。
  • 单段直道长度是两段直线中其中一段的长度，单位是米。
  • 弯道半径是两端半圆的半径，单位是米。
  • 默认直道 84.39 米、半径 36.8 米，周长约 400 米。不同跑道请按实际尺寸调整。

跑道周长 = 2 × 直道长度 + 2 × π × 弯道半径。仅改变周长不会修正中心位置；仅移动中心也不会改变方向或尺寸。

Windows 地图的“把跑道移到画面中心”和 Android 地图的“移到画面中心”，会把跑道中心移到当前视野中心；调整后仍需点击“应用”才会回填。

手动输入时选哪个坐标来源

坐标来自哪里 Windows 主界面 / 两端 GPX 导入时的选择
标准 GPX、GPS 设备、Google 地球；明确已转为 WGS84 的文件 GPS / WGS84
明确未经转换的高德、腾讯坐标 高德 / 腾讯 / GCJ-02
明确未经转换的百度坐标 百度 / BD-09

Windows 的手动输入默认选择高德 / 腾讯；确认自己的数据来源后再填。通过应用地图回填的坐标会自动按 WGS84 使用。

Android 主界面的中心坐标只填写 WGS84；若坐标来自高德或百度，请先转换，或使用内置地图选点。Android 导入 GPX 时可以单独选择三种来源。

不要仅凭文件来自某款运动应用就假定它需要转换：有些导出工具已经做过转换，再转换一次反而会产生偏移。

Android“使用当前位置”

点击按钮并授予定位权限后，应用读取设备最近一次可用位置。该位置可能来自之前的定位，且你所站的位置通常不是跑道中心；请在地图中确认并微调。若没有可用位置，先开启手机定位，或改用地图 / 手动输入。

地图没有跑道细节怎么办

底图使用 OpenStreetMap，部分地区信息不完整。可以采用准确的手动数据，或导入自己记录的 GPX。地图搜索和瓦片需要联网；无法联网时，已知坐标的跑道生成和 GPX 导入仍可使用。

Windows 的地图校准页依赖应用保持运行。关闭应用后，旧地图页会失效；重新打开应用并点击地图按钮即可获得新的页面。

5. 导入 GPX 并沿原路线生成

GPX 是轨迹输入，FIT 是本应用的导出文件。导入 GPX 会使用路线几何信息；原文件的时间、心率和其他生理数据不会原样复制。

  1. 点击“导入 GPX…” / “导入 GPX”，在文件选择器中选取自己的 .gpx 文件。
  2. 在“GPX 坐标来源”对话框中确认 WGS84、GCJ-02 或 BD-09，按实际来源选择后导入。
  3. 若文件有多个 trkseg 或 rte 分段，默认使用第一段；在分段下拉框中选择要生成的一段。
  4. 查看预览，确认路线形状和端点。绿色圆点是起点，橙色圆点是终点。
  5. 应用自动计算该段距离并锁定距离及跑道几何输入。填写时长、平均步频和可选步幅，设置开始时间。
  6. 按对应平台的保存流程导出 FIT。Windows 仍可以按当前选中的同一段路线批量生成。
  7. 若要回到跑道模式，点击“切回标准跑道”。距离会回到默认 5 公里，请重新检查运动数据和跑道位置。

GPX 模式不会把路线拉伸到指定距离，也不会自动闭合、重复绕圈或拼接断开的轨迹段。想换一段路线时，请切换下拉框；想让一条短路线重复绕圈，需要先准备相应的 GPX 文件。

文件应包含至少两个不同位置的有效轨迹点。过大、损坏、坐标无效或含 DTD / 实体声明的文件会被拒绝；请先从原始设备重新导出或裁剪轨迹。

6. 运动参数与自定义步幅

参数 单位和允许范围 填写提示
距离 km；0.001～1000 GPX 模式由路线计算并锁定
时长 分钟；1 秒～24 小时 必须能换算成整秒，如 0.5 分钟 = 30 秒
平均步频 双脚总步数 / 分钟；30～300 的整数 170 表示一分钟总共迈 170 步
步幅 米 / 每一步；0.01～6.5，或留空 0.80 表示每步 80 厘米；不是 80 米，也不是两步距离
中心纬度 / 经度 度；纬度 -85～85，经度 -180～180 纬度、经度分开填，并确认坐标来源
跑道方向 度；0～360 从正北顺时针测量长轴方向
单段直道长度 米；1～1000 默认 84.39
弯道半径 米；5～300 默认 36.8

填写小数请使用英文小数点，例如 0.80。允许范围是输入边界；距离和时长也需要搭配成合理的速度，过大的组合仍可能超过 FIT 编码范围。

自动步幅

步幅留空时：步幅（米 / 步）= 距离（米）÷ 时长（分钟）÷ 步频（步 / 分钟）。

例如 5000 米、30 分钟、170 步 / 分钟，总步数约为 5100，步幅约为 0.9804 米 / 步。改变距离、时长或步频后，自动步幅随之变化。

自定义步幅

填入 0.80 后，应用将每一步长度写为 0.80 米，并在预览中标注“自定义”。该数值用于逐秒记录和 lap / session 的平均步幅。清空输入框就恢复自动计算。

自定义步幅不会自动改变距离、时长或步频。若要四项数据满足“距离 = 步幅 × 总步数”，请自行协调输入，或者使用自动步幅。例如 5 公里、30 分钟、170 步 / 分钟搭配 0.80 米 / 步时，按步数推算只有约 4.08 公里；应用仍会按你输入的 5 公里输出路线距离。

FIT 内部步幅编码精度为 0.1 毫米；超过该精度的小数会按编码精度舍入。不同运动平台也可能自行重算指标或忽略步幅字段。

7. 开始时间、保存位置与批量导出

开始时间

使用本机 / 手机当前时区解释开始日期和时间。Windows 日期格式为 年-月-日（如 2026-10-02），时间为 24 小时制 时:分（如 08:30）；Android 使用日期与时间选择器。

运动结束时间由开始时间加上时长计算。生成文件的时间与运动开始时间是两回事，日期不会因点击保存而自动替换。

Windows 单份保存

  1. 将“生成份数”设为 1。
  2. 选择保存目录；默认目录为用户目录下 Desktop/FIT文件，也可以换成任意可写目录。
  3. 点击“生成 .fit 文件”，等待完成，再点击“打开输出文件夹”。

文件名包含运动开始时间和导出时的标识，避免静默覆盖已有文件。若默认目录不便查找，直接通过选择按钮换成明确的目录。

Windows 批量生成

  1. 先设好一份运动的参数和开始时间。
  2. 将“生成份数”设为 1～100。
  3. 设置“每次间隔（小时）”，范围为 0～8760。例如 24 表示每份的开始时间相隔一天。
  4. 多份任务的间隔不得短于单份运动时长，避免运动时间重叠。
  5. 总记录数不得超过 50 万；每份约有“时长秒数 + 1”条逐秒记录。遇到限制时减少份数或时长。
  6. 点击生成并等待完成。文件使用相同路线、距离、时长、步频和步幅，各份开始时间依次顺延。

例如开始时间为 10 月 2 日 08:30，生成 3 份、间隔 24 小时，对应 10 月 2、3、4 日各 08:30 开始。

Android 保存

每次点击“保存 FIT 文件”导出一份。系统文件选择器允许选择保存位置和文件名，应用不会自动把文件存入固定的“FIT文件”文件夹。取消文件选择器不会完成导出；看到“已保存到手机”后才表示写入完成。

若需要下一份，回到应用修改开始时间或其他参数，再保存一次。目标位置若选择云盘提供方，该提供方可能同步文件；选择设备本地目录即可保留在手机。

8. 导出后怎么检查和使用

  1. 确认应用显示生成 / 保存成功，并到选择的位置找到 .fit 文件。
  2. 使用支持 FIT 的查看器或目标运动平台提供的正式导入入口，选择这个文件。
  3. 导入后检查开始时间、距离、时长、路线，以及平台是否读取步频 / 步幅。
  4. 平台的导入入口和字段支持会随版本变化，本说明不保证任何特定平台或账号能接受生成数据。批量生成前可先用一份文件确认兼容性。

本应用生成的是按输入模型构造的运动记录。心率、功率、海拔等辅助数据属于设定或模型估计；它们不是传感器实测。Windows 还会写入估计的触地时间和热量。应用不记录你是否实际完成运动。

生成路线按距离等速采样，标准跑道起点由几何模型确定；GPX 起点是所选段的第一个点。文件能正确解码不等于平台会读取所有指标。

9. 常见问题

点击生成提示“请检查输入”

检查是否漏填跑道中心、日期或时间；确认数字中没有单位文字或中文小数点。步频必须是整数，时长必须换算成整秒。步幅可以留空，其他当前模式必填项需要完整填写。

地图打开后空白、搜索失败或看不到跑道

先确认网络连接。底图和搜索来自外部服务，可能暂时不可用；不需要 API Key。可重新打开地图，或改用准确的手动坐标 / GPX。Windows 请保持应用运行，不要使用已关闭应用留下的旧地图页。

路线整体偏移

检查坐标来源选择、是否重复转换，以及中心是否取在跑道中心。Android 主界面只能填 WGS84。若位置正确但轮廓错位，再检查方向和跑道尺寸。

距离或跑道输入变灰，不能编辑

这是 GPX 原路线模式：距离和跑道几何由轨迹决定。可修改时长、步频和步幅；点击“切回标准跑道”恢复跑道参数输入。

导入 GPX 后只看到一段路线

查看分段下拉框。应用默认加载第一段，各段独立处理，避免把中断的位置强行连接起来。

Android 定位按钮没有拿到位置

确认手机定位已开启并授予权限。按钮使用设备最近位置；没有可用位置时改用地图校准或手动输入 WGS84。导出 FIT 本身不依赖定位权限。

导出后找不到文件

Windows 点击“打开输出文件夹”；Android 到系统文件选择器中最后选定的位置查找。确认没有取消保存，并等到应用明确提示成功。文件名通常以 run_ 开头。

Android 无法覆盖安装或解析安装包失败

确认系统为 Android 8.0 或更高、下载已完成，必要时重新下载并核对 SHA-256。签名不同的调试版和正式版无法直接覆盖；导出的文件应先保留在自己选择的目录。内置说明与 FIT 保存不需要安装额外插件。

平台显示的步幅与输入不同，或不显示步幅

平台可能忽略该字段或根据距离、时间、步频重新计算。先核对单位：0.80 是 80 厘米 / 步。若希望各项关系一致，可将步幅留空自动计算；本应用无法控制外部平台的解析方式。

生成中报错或 Windows 不能关闭

查看错误信息和 Windows 日志，检查输出目录是否可写、距离与时长是否合理、磁盘空间是否足够。Windows 导出期间会要求等待任务结束再关闭。Android 写入失败时检查目标位置是否仍可访问，再重新保存。

10. 离线能力、隐私和更新

  • FIT 生成、GPX 解析和内置操作说明都可离线使用。在线地图底图和地点搜索需要联网。
  • GPX 文件和 FIT 数据在本机处理，应用没有账号系统，不主动上传运动记录。
  • 地图服务会收到当前视野的瓦片请求；主动搜索时，地点关键词会发送给搜索服务。
  • Windows 地图页通过本机回环地址与应用通信，不在局域网上提供服务；Android 在应用内打开地图。
  • 使用系统文件选择器选到云盘目录时，文件后续同步由该文件提供方处理。
  • 应用当前不提供完整设置的保存 / 恢复入口；重新打开后请重新核对输入。已导出的 FIT 文件需要自行保管。
  • 更新时从项目发布页下载新版本。Windows 运行新版 EXE；Android 安装同一签名的新版 APK。
